# RoutePeek UX 增强设计文档

> 让小白能看懂自己电脑的网络拓扑
> 版本: v2.0 设计 | 日期: 2026-04-24

---

## 1. 设计目标

### 核心问题

当前 RoutePeek 虽然能采集完整的网络信息，但展示方式偏向技术人员：
- 拓扑图是纵向 div 列表，无真实连线，看不出设备间关系
- 全是技术术语（ens38、MTU 1500、metric 100），小白无法理解
- 诊断结果与拓扑图分离，无法直观看出「哪里出了问题」
- Traceroute 显示裸 IP 和 RTT 数字，非技术人员难以理解

### 设计原则

1. **可视化为中心** — SVG 分层拓扑图是页面主角，一眼看懂网络结构
2. **双层信息** — 大白话在上，技术参数可展开，服务不同用户
3. **诊断联动** — 问题直接标注在拓扑图上，不需要跳转
4. **场景化** — 一句话总结网络状态，预设常用操作

### 技术约束

- 方案 A：渐进增强现有单文件 `index.html`
- 不引入前端框架，保持 vanilla HTML/CSS/JS
- 不引入 D3 等外部库，SVG 用原生 JS 生成
- 保持 `go:embed` 单二进制部署
- 后端 API 接口不变，仅前端展示层改造
- 唯一后端改动：扩充 VPN 前缀列表（consts.go）

## 2. SVG 分层拓扑图

### 2.1 分层结构

将网络拓扑分为 3 个水平层，从上到下代表数据流向：

**Layer 1 — 本机层（LAN）**
- 中央大节点：「我的电脑」
- 左右展开所有网卡（ens33, docker0, wlan0 等），每个网卡用不同颜色图标区分类型
- 网卡之间用虚线连到本机节点

**Layer 2 — 中间层（Gateway / VPN / Proxy）**
- 默认网关节点（路由器图标）
- VPN 隧道节点（盾牌图标，如果有）
- 代理节点（如果有）
- DNS 服务器节点
- 用实线 + 流动粒子动画连接到上层

**Layer 3 — 外网层（WAN）**
- 公网出口 IP 节点
- 互联网云图标
- 带归属地标签

### 2.2 SVG 实现

- JS 动态生成 inline SVG（不引入 D3 等库）
- 节点位置通过数学计算布局（每层内根据节点数量均匀分布）
- 连线使用 SVG `<path>` 贝塞尔曲线，带 `stroke-dasharray` 流动动画
- 每个节点 hover 弹出解释面板（tooltip）
- 诊断问题节点有红色/橙色脉冲光环

### 2.3 节点类型与配色

| 节点类型 | 图标 | 主色 | 说明 |
|----------|------|------|------|
| 本机 | 🖥️ | cyan | 我的电脑 |
| 有线网卡 | 🔌 | cyan | ethernet 类型接口 |
| 无线网卡 | 📶 | green | wifi 类型接口 |
| VPN 隧道 | 🔒 | red | vpn 类型接口 |
| Docker | 🐳 | #6bcbff | docker/容器网络 |
| 虚拟机 | 🖥️ | orange | vm 类型接口 |
| 网关 | 📡 | orange | 默认网关/路由器 |
| DNS | 🔤 | green | DNS 服务器 |
| 代理 | 🌐 | cyan | HTTP/HTTPS 代理 |
| 公网出口 | 🌍 | purple | 公网 IP |
| 互联网 | ☁️ | purple | Internet 云节点 |

### 2.4 与现有实现对比

| 现在 | 改进后 |
|------|--------|
| 纵向 div 列表，平铺无连线 | SVG 分层图，有真实连线 |
| 只显示 1 个网关、1 个 DNS | 展示所有网卡、所有 DNS |
| 无法看出哪些网卡走哪条路由 | 连线表示网卡→网关的路由关系 |
| 静态不可交互 | hover 弹出解释，点击展开详情 |

## 3. 通俗解释系统

### 3.1 双层信息架构

每个网络组件都有两层展示：

**第一层（默认可见）— 大白话**
- `ens38` → 「📶 有线网卡 · 连接到你的路由器 · IP 192.168.1.63」
- `docker0` → 「🐳 Docker 虚拟网桥 · 用于容器通信 · IP 172.17.0.1」
- `cnem_vnic` → 「🔒 VPN 隧道 · 你的流量正在加密传输」
- 默认网关 → 「📡 路由器 · 你家/公司的网络出口 · 所有上网流量都经过这里」
- DNS → 「🔤 域名解析器 · 把网址翻译成 IP 地址」

**第二层（点击展开）— 技术详情**
- 完整参数：MAC、MTU、路由 metric 等
- 面向进阶用户

## 4. 诊断增强

### 4.1 拓扑联动

- 有问题的节点显示脉冲光环（红色=严重，橙色=警告）
- hover 节点时，tooltip 显示诊断结果和建议
- 首页直接展示诊断问题面板，不需要跳转到独立 tab

### 4.2 诊断文案优化

从技术描述改为三段式：**现象 → 意味着什么 → 建议**

示例（DNS 异常）：

> 🔤 你的域名解析器（DNS）使用的是 10.10.3.197，这不是常见的公共 DNS 服务器。
>
> **这意味着什么？** 你访问网站时，需要先把网址翻译成 IP 地址。如果 DNS 被篡改，你可能被导向假网站。
>
> **可能的原因**：① 公司/学校内网分配 ② 路由器自带 ③ DNS 被劫持
>
> **建议**：如果不确定来源，可改为公共 DNS：8.8.8.8（Google）或 223.5.5.5（阿里）

### 4.3 新增诊断项

| 诊断项 | 说明 |
|--------|------|
| 多网卡路由冲突 | 多张网卡同时活跃但默认路由指向同一网关 |
| WiFi + 有线同时连接 | 提示可能存在路由优先级问题 |
| 无公网 IP | 公网 IP 获取失败，可能网络不通 |
| VPN 分流检测 | 全局 VPN 可能影响局域网访问速度 |

## 5. 路径追踪优化

### 5.1 场景化入口

提供预设按钮，小白不需要知道该输入什么：

- 🔵 测试百度（baidu.com）
- 🟢 测试谷歌（google.com）
- 🟠 测试 DNS（8.8.8.8）
- 自定义输入框

### 5.2 跳跃点分区着色

| 区域 | 颜色 | 判断逻辑 |
|------|------|----------|
| 🏠 本地网络（1-2 跳） | 青色 | 私网 IP 段 |
| 🏢 运营商骨干（中间跳） | 橙色 | 公网 IP + 归属地判断 |
| 🌐 目标服务器（最后跳） | 紫色 | 最后几跳 |

### 5.3 每跳通俗解释

- 第 1-2 跳标注「路由器 / 上级网关」
- 超时跳明确说明「这很正常，很多路由器拒绝回复探测包」
- 中间跳标注运营商归属地
- RTT 用颜色条可视化（绿 <20ms / 黄 20-100ms / 红 >100ms）

### 5.4 追踪完成总结

> 「你的数据到达 baidu.com 经过了 **12 个节点**，总延迟约 **35ms**（很快 ✅），途经 **中国电信** 骨干网络」

## 6. UI 布局重构

### 6.1 Tab 结构调整

| 现在（5 个 tab） | 改进后（3 个 tab） |
|------|--------|
| 总览 / 接口 / 路由 / 诊断 / 追踪 | **网络全景** / **详细信息** / **路径追踪** |

- **网络全景**（默认）：状态摘要 + SVG 拓扑图 + 统计条 + 诊断问题
- **详细信息**：网卡列表 + 路由表 + DNS 配置（进阶用户）
- **路径追踪**：场景化追踪 + 分区可视化

### 6.2 首页布局（网络全景）

1. 一句话状态栏
2. SVG 分层拓扑图（视觉中心）
3. 快速统计条
4. 诊断问题面板（仅在有问题时出现）

### 6.3 交互设计

| 功能 | 说明 |
|------|------|
| 节点点击展开 | 拓扑图节点点击后展开详情面板 |
| 问题节点闪烁 | 有诊断问题的节点持续脉冲动画 |
| 连线流动动画 | SVG 连线上流动粒子表示数据流向 |
| 首次引导 | 提示「点击拓扑图上的任意节点，了解它的作用」 |

## 7. 后端改动（最小化）

### 7.1 VPN 前缀扩充（consts.go）

新增前缀：`tailscale`、`nordlynx`、`warp`、`mullvad`

### 7.2 VPN 后备检测（vpn.go）

如果接口名不匹配已知前缀，但路由表存在指向该接口的 0.0.0.0/0 路由且非默认网关，标记为疑似 VPN。

### 7.3 不变的部分

- API 端点不变
- CLI 工具不变
- go:embed 嵌入方式不变
- 数据结构不变
