# RoutePeek Internationalization (i18n) Design

## Overview
This document outlines the design for implementing internationalization (i18n) in the RoutePeek project, providing both Chinese (default) and English support across the Web UI, CLI, and documentation.

## 1. Web UI Internationalization
We will use a lightweight, dynamic JavaScript approach in the frontend.
*   **Dictionary**: Add a `const i18n = { zh: {...}, en: {...} }` mapping inside the JavaScript in `cmd/server/static/index.html`.
*   **HTML Binding**: Add a `data-i18n="key"` attribute to all static HTML elements containing text.
*   **Toggle Logic**: Create a `setLanguage(lang)` function to iterate over `[data-i18n]` elements and update text, as well as handle dynamically injected content.
*   **UI Element**: Add a 🌐 toggle button in the navigation bar. Preference is saved to `localStorage`.
*   **Default**: Chinese (`zh`).

## 2. CLI Internationalization
We will implement a custom, lightweight map-based i18n package for the Go CLI.
*   **Package**: Create `internal/i18n` with translation maps for `en` and `zh`.
*   **Detection**: Automatically detect the OS locale by reading `LANG`, `LANGUAGE`, or `LC_ALL` environment variables. Default to `zh` if English is not detected.
*   **Implementation**: Provide an `i18n.T("key", args...)` function and replace user-facing text in `cmd/cli/main.go`, `internal/discovery/print.go`, and `internal/diagnostic/diagnose.go`.

## 3. Documentation
*   **README**: Retain `README.md` as the default Chinese documentation.
*   **English Docs**: Create `README_en.md` for the English version.
*   **Cross-linking**: Add `[English](README_en.md) | [中文](README.md)` at the top of both files.
